## Why

Agents can currently see an unavailable repository index and immediately fall
back to filesystem inspection. That bypasses Astrograph at the moment it is
most useful and makes its adoption depend on a manual first-index step.

## What Changes

- Require the Astrograph exploration path to create a missing repository index,
  wait for hydration, and retry the requested retrieval before fallback.
- Ensure Astrograph's own TypeScript configuration can load before the package
  has been built.
- Make the recovery outcome explicit when indexing or retrying fails.
- Preserve current explicit setup choices; this does not introduce background
  indexing or automatic repository writes at installation time.

## Capabilities

### New Capabilities

- `repository-index-hydration`: Recover a missing Astrograph repository index
  during an agent's first code-exploration request.

### Modified Capabilities

- None.

## Impact

- Agent guidance generated by the installer and repository policy.
- The source-checkout `astrograph.config.ts` contract.
- Index/readiness behavior and its focused contract tests.
- No new dependency, network request, telemetry, or background process.
